Owner's machine (Intel UHD / Mesa 26.1.8 unless noted), 1280×720, `ar_debug` textures, scenes from
`tools/testscene/scenes/`. Section counts come from the terrain stats in each shot's `.meta` (development.md 2.5).

| Intel UHD, Normal | 254.0 / 124.0, 6.72 | 392.3 / 207.5, 4.26 | +54% | +67% |
| GTX 1650 Ti (PRIME), Normal | 873.6 / 334.4, 2.49 | 973.8 / 276.1, 2.55 | +11% | −17% |

**Intel Short and Tiny are missing:** the laptop throttled partway through the first set (both renderers plateaued at

on the game's own code and the low is a handful of slow frames (meshing uploads at the orbit's edge); to look at with
GPU timers in Phase 4 (gl45 fast paths).

## Phase 3: the rest of the frame (2026-11-12, development.md 3.1–3.8)

Intel UHD, 1280×720, Fancy, smooth lighting, Normal distance. Where the frame's time went before and after:
`b1.7.3-profile.md`.

**Busy scene** (`busy_bench`: 80 mobs, rain, the orbit; 25 s measured; runs back to back):

| | avg FPS | 1% low | p99 ms | CPU (% of a core) |
|---|---|---|---|---|
| the game's renderer (Altrender off) | 163.2 | 111.8 | 8.59 | |
| Altrender, Phase 3 (stream off: the default) | 209.3 / 212.0 | 143.1 / 149.0 | 6.52 / 6.29 | 59 |
| Altrender, Phase 3, stream on | 208.8 / 211.7 | 137.2 / 141.3 | 6.57 / 6.34 | 64–65 |
| GTX 1650 Ti: stream off / on | 781.8 / 730.4 | 270.4 / 294.1 | 2.47 / 2.21 | |

A JFR recording during the window costs the 1% low (60–63 instead of ~140: JFR instruments classes on the main
thread); those runs only count for profiles.

**Entity culling (3.5)** (`cave_entities` + a 15 s bench turning in place, `-Daltrender.debug.orbitRadius=0`): 1,069.1
→ 1,226.6 FPS (+15%), 1% low 439.7 → 515.0; 34 objects skipped; pixels identical.

**Frame limit (3.6)** (power saver, 40 FPS, `bench_orbit`): frame-time stdev 249 µs with the LWJGL2-style limiter,
**19 µs** with Altrender's; p1–p99 24.09–25.21 ms → 25.00–25.08 ms.

**Minimised (3.6)** (`-Daltrender.debug.forceIdle`, 10 FPS; CPU of the whole process over the window): turning in
place, **1.5%** of a core (uncapped: 59.8% at 407 FPS). Orbiting, 10.2%: the moving camera keeps the mesh threads
building sections at the range's edge, and the JIT is still compiling at 10 FPS; a minimised game doesn't move.

**Allocation (3.7)** (JFR allocation samples, busy scene, MB/s): Altrender's code on the main thread 17.3 → 1.4; mesh
threads 32.6 → 5.6. The main thread's total swings between runs (22–94 MB/s): the game's own chunk lookup boxes an
`Integer` per call (weather asks it per column), and whether the JIT removes the box differs run to run.

**Soak (3.7/3.8)** (`busy_bench` orbiting for 30 minutes, G1, default heap): 379,287 frames, 210.7 FPS average,
1% low 83.7; 0 driver errors, no GL objects left at shutdown; 111 GC pauses, max 8.68 ms (above 10 ms only the
explicit `System.gc()` of the game's world load and the harness's heap checks). Live heap 115 → 128 MB: the harness's
own frame-time list (a boxed `Long` per frame); with a primitive array, a 6-minute rerun stays at 116 MB after every
GC.

## Phase 4: gl45 vs gl33 vs the game (2026-11-12, development.md 4.6)

`bench_orbit` (Normal, Fancy, smooth lighting), 1280×720. The first run of a batch is left out: twice it came in at
~90 FPS on both GPUs (machine state, not the renderer).

| GPU | Renderer | avg FPS | 1% low | p99 ms | terrain draw calls (layer 0 / 1) | terrain CPU per frame |
|---|---|---|---|---|---|---|
| Intel UHD | the game's | 255.9 | 140.3 | 6.51 | | |
| Intel UHD | Altrender gl33 | 344.7 | 207.7 | 4.40 | 8 / 89 | 328 µs |
| Intel UHD | **Altrender gl45** | 343.5 | 200.9 | 4.36 | 1 / 1 | 256 µs |
| Intel UHD | gl45, GPU-written commands | 326.9 | 206.5 | 4.45 | 1 / 1 | 237 µs |
| Intel UHD | gl45, no indirect draws | 342.0–345.1 | 205–215 | 4.30–4.41 | 8 / 89 | 300 µs |
| GTX 1650 Ti | the game's | 865.3 | 313.7 | 2.66 | | |
| GTX 1650 Ti | Altrender gl33 | 972.7 | 357.1 | 1.71 | 8 / 89 | 155 µs |
| GTX 1650 Ti | **Altrender gl45** | 974.8 | 396.2 | 1.76 | 1 / 1 | 146 µs |
| GTX 1650 Ti | gl45, GPU-written commands | 937.0 | 302.1 | 2.56 | 1 / 1 | 142 µs |
| GTX 1650 Ti | gl45, no indirect draws | 976.5 | 320.8 | 1.82 | 8 / 89 | 196 µs |

(Fancy draws layer 1 twice, depth then colour: per frame 8 + 89 + 89 draws on gl33, 3 on gl45.)

- **gl45 = gl33 in FPS here:** Intel is GPU-bound and NVIDIA is bound by the game's own CPU work, so fewer draw calls
  show only as CPU time: terrain submission −22% (Intel) / −6% (NVIDIA). Whole frame GL calls (apitrace, overworld_day):
  1,236 (gl45) vs 1,683 (gl33); 0 maps or unmaps and 0 `glUniform*` per frame on both.
- **The earlier backend's Intel-Mesa finding (indirect draws slower than plain multi-draw) doesn't reproduce:** alternating
  runs, 343.5 vs 345.1 / 342.0. No driver rule.
- **GPU-written commands are 0–4% slower** (a compute dispatch and barrier per frame for ~300 sections): off by
  default (Review), for cameras the visibility walk can't serve (shadow passes).
- **Phase 2's NVIDIA 1% low deficit is gone** (it was −17% against the game; now +14% gl33, +26% gl45).
- **First mistake, fixed:** the stream ring in client storage cut NVIDIA's gl45 to 175 FPS (commands and per-draw data
  read from system memory).

**Program builds (4.5)**, 200 distinct terrain-program variants (salted: no shader cache), until all are built:

| GPU | `KHR_parallel_shader_compile` | without | render thread inside GL with it |
|---|---|---|---|
| Intel UHD / Mesa | 1,053 ms | 1,097 ms | 1,053 ms (Mesa parses and links on the calling thread) |
| GTX 1650 Ti | **382 ms** | 968 ms | 382 ms (1.7 ms to issue each build) |

A shader pack's loading screen should issue a few builds per frame and poll the rest (AltShaders, Phase 6).
